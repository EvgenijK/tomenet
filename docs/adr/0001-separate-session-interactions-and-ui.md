# Разделение состояния сессии, игровых взаимодействий и UI

2026-09-21, раунды Q4–Q6. Для переноса игровых возможностей и дальнейшей переработки UX разделяем модель сессии, игровое взаимодействие, UI и протокол: модель хранит известные клиенту данные и запросы сервера; взаимодействие ведёт выбор, отмену и подготовку смысловой команды; UI представляет данные и передаёт смысловой ввод; протокол переводит команды и входящие данные в формат согласованной версии сервера. Незавершённое взаимодействие имеет явное состояние, а сервер остаётся авторитетом игровых результатов; мышь, клавиатура и макросы используют общую семантику с сохранением особенностей behavior baseline.

Сохраняем проверенные правила и самостоятельные legacy-функции, но разрешаем перерабатывать связанные с терминалом сценарии по одной возможности с проверкой совместимости, включая отмену и макросы. Это требует изменений существующего кода, зато позволяет менять представление и способы ввода независимо от сетевой логики; начатая SV-реализация также может быть переработана под эти границы.

Механизм доставки между модулями, потоки и конкретные C-интерфейсы этим решением не определены. Сравнение альтернатив: [исследование](../research/sv-client-architecture.md).
