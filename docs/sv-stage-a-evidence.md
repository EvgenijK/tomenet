checkpoint. It requires all eight A outcomes: HP, message occurrences, key answer,
key cancellation, Linux build, Windows build, software renderer and one window.
It never accepts a full capability, human review or the complete client.

The environment matrix is Linux software + accelerated, and MinGW i686 under

## Reviewed dependency scope

The producer retains fingerprints **before** native scenarios and validates them
again after the run. Inventories exhaustively include regular files, including
untracked/ignored additions and removals. Symlinks in these directory scopes still
fail closed. Evidence/artifacts live in a separate output root.

| Root/scope | Inputs and reason for scope |
|---|---|
| `tomenet=checkout`, `src/` | All SV production modules, temporary peer, used common sources/headers, makefiles, generated object/dependency/link metadata and final binaries. Broad enough to detect a new include or source beside an existing input. |
| `tomenet`, `tests/` | All fixture producers, protocol literals, scenario runners, sanitizer and data/CLI checks; no test-only implementation substitutes for SV. |
| `tomenet`, `tools/` | Build/SDK preparation, evidence producer, checker, checkpoint mapping and provenance algorithms. |
| `tomenet`, `docs/capabilities/` | Schemas, registry/ledger, reconciliation data and validator contracts used by the automated gate. |
| `tomenet`, `lib/` | Entire explicit library/resource discovery tree, including bundled TTF/PCF and licenses. Temporary profile/overlay/failure fixtures are generated by the fingerprinted runners; existing user configuration is deliberately not loaded. |
| `mingw-sdk=--mingw-sdk`, `.` | Full pinned SDK root, including SDL/TTF/FreeType source, compiler configuration, SDK metadata, headers, import/static libraries and DLLs. Its absolute location is retained by the command report. Missing root is unavailable, changed contents are stale. |
| `stage-a=--output`, `wine-bin/` | Actual staged executable, DLLs and stage metadata, separately from their SDK sources. |

These are reviewed `impact: complete` directory scopes, not `.d`-derived lists.
The selected build logs identify the exact `build.txt` files. Their include/library
search flags and `.d` paths are checked against source/test, host and selected SDK
roots; an unknown path blocks production. Old unused build-cache configurations
are fingerprinted with `src/`, but do not define the active build's search paths.

`host-provenance.json` is an additional content-addressed dependency artifact.
The Arch/Manjaro producer expands installed package dependencies from the local
pacman database, starting with compilers/linkers, CMake/curl, make/pkgconf, MinGW, Wine,
Python, SDL/TTF/FreeType, Mesa/libglvnd/Vulkan, fontconfig and shell utilities.
It fingerprints package metadata, installed files in `/usr`, `/etc`, `/opt` and
standard binary/library aliases, whole `/usr/include`, `/usr/lib` and `/usr/bin` search trees, dynamic-loader cache/configuration and local
include/library trees, plus the **entire active Python virtual environment**.
Directory membership and symlink chains are retained, not just today's used
header names. Link targets are fingerprinted separately. Actual resolved command
paths must belong to this closure. SDL's dynamically loaded graphics libraries
are covered beyond direct ELF `DT_NEEDED` entries.

Volatile `/proc`, `/sys`, `/dev`, `/run` and package-owned `/var` state are not
compilation inputs; local pacman metadata is retained separately. The standard
`/etc/mtab -> /proc/self/mounts` link is retained, but its process-specific target
is not a static dependency (the checker necessarily runs in another process). Unreadable
package files/directories are explicitly recorded with permission/ownership/size
and must remain unreadable: this unprivileged producer cannot consume them.
Changing access changes provenance. Generated test profiles and Wine prefix state
are observations, not reused build inputs. Their producers and staged inputs are
fingerprinted. No credentials or file contents are copied into provenance.

Host provenance is captured before builds. Build/loader/Python environment
injections such as `CPPFLAGS`, `CPATH`, `LD_LIBRARY_PATH` and `PYTHONPATH` are
rejected rather than silently widening the reviewed scope. The current producer
is deliberately specific to the installed Arch/Manjaro host; another distribution
needs an equivalent reviewed producer. Hashes prove freshness, not the truth of
scenario reports or completeness of a dishonest producer's declaration.

External roots stay explicit and available on the producing machine. Rechecking
an archived run needs the same source/SDK/host bytes and staged executable. Moving
or deleting them does not turn the historical observation into fresh evidence.
There is no repository-wide self-referential digest and no automatic human signoff.

## Reproduction

```sh
/tmp/sv15-venv/bin/python -B tools/run_stage_a.py \
  --output /tmp/sv18-final-evidence \
  --mingw-sdk /tmp/sv16-sdk-final --sdk-downloads /tmp/sv16-downloads

/tmp/sv15-venv/bin/python -B tools/validate_capabilities.py \
  --manifest docs/capabilities/manifest.json \
  --ledger /tmp/sv18-final-evidence/candidate-ledger.json \
  --evidence /tmp/sv18-final-evidence/candidate-evidence.json --checkpoint stage-a \
  --source-root tomenet="$PWD" \
  --source-root stage-a=/tmp/sv18-final-evidence \
  --source-root mingw-sdk=/tmp/sv16-sdk-final
```

Use a new output directory on every run. The full runner requires native display
access for SDL/Wine and an environment supporting LeakSanitizer. It checks data,
registry/reconciliation, HTML sync, sanitizer suites, existing clients, native
Linux and Wine scenarios. Its report keeps optional Wine Direct3D failures visible;
it does not substitute a Direct3D observation for the required software run.

`tests/sv_checkpoint_checks.py` uses the production CLI to verify sufficient
synthetic input matrices and rejection of artifact/dependency mutations, missing
SDKs, new header/resource files, incomplete runtime, missing obligations, invalid
checkpoint/platform identity and attempts to promote a checkpoint to full
acceptance. These validator fixtures are not imported as native observations.
