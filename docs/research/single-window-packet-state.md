# Incoming packet fields to semantic presentation state

## Scope and result

This inventory covers the play-session byte dispatcher, every compiled registration in `Receive_init`, every `Receive_*` implementation declared in `netclient.h`, the pre-play handshake receivers, and the nested record scans performed by compound packets. Packet numbers come from `pack.h`; the dispatcher indexes the first unsigned byte into a 256-entry table and locks the socket buffer around each receiver ([src/client/nclient.c:337](../../src/client/nclient.c#L337), [src/client/nclient.c:1844](../../src/client/nclient.c#L1844), [src/common/pack.h:21](../../src/common/pack.h#L21)).
The implementation-ready boundary is: decode wire values into semantic snapshots, keyed collections, modal requests, or ordered events before rendering. Raw/formatted payloads called out below are retained losslessly alongside any parsed form. This is required because the current receiver often renders immediately or stores only a decorated string; reconstructing the original server assertion from terminal cells is impossible.
## Wire and failure rules

`Packet_scanf` defines `%c` as one raw byte, `%hd/%hu` as signed/unsigned two-byte big-endian values, `%d/%u` as signed/unsigned four-byte big-endian values, and `%s/%S/%I` as NUL strings bounded by `MAX_CHARS`/`MSG_LEN`/`ONAME_LEN` ([src/common/sockbuf.c:649](../../src/common/sockbuf.c#L649), [src/common/sockbuf.c:671](../../src/common/sockbuf.c#L671), [src/common/sockbuf.c:713](../../src/common/sockbuf.c#L713), [src/common/sockbuf.c:779](../../src/common/sockbuf.c#L779)). The string scanner truncates at its destination limit instead of retaining overflow bytes, so the new decoder must either reject oversize frames deterministically or retain the full framed payload before compatibility truncation ([src/common/sockbuf.c:802](../../src/common/sockbuf.c#L802)).
Under `SOCKBUF_LOCK`, incomplete input returns zero without advancing; format/read failure returns -1; success advances exactly the decoded byte count ([src/common/sockbuf.c:892](../../src/common/sockbuf.c#L892)). `Net_packet` waits on zero with no progress, clears ambiguous partial progress, and clears/disconnects on -1. Unknown/NULL packet entries send `PKT_UNKNOWNPACKET`, request redraw, and clear the entire receive buffer ([src/client/nclient.c:1854](../../src/client/nclient.c#L1854), [src/client/nclient.c:1870](../../src/client/nclient.c#L1870)). Unless a row overrides it, “abort” below means these shared rules.

## Lossless fallback envelope

For every successfully decoded incoming unit, capture `{packetId, negotiatedServerVersion[6], compiledFeatureSet, arrivalSequence, rawStartOffset, rawLength, rawBytes, selectedWireVariant}` before applying compatibility transforms. Compound records commit the envelope only after their receiver's rollback boundary succeeds. The semantic payload then stores typed decoded fields; direct cells additionally store `{surfaceRole, x, y, fgAttr, fgCodepoint, bgAttr?, bgCodepoint?, repeat?}`, and positioned/formatted text stores `{surfaceRole, line, column?, attr, rawTextBytes, parsedSpans}`. This envelope is the minimum that can replay old byte-width glyphs, RLE, in-band colour markers, sentinels and version defaults without reconstructing them from terminal cells; the dispatcher already exposes `old_ptr` before each receiver and successful scans advance `rbuf.ptr`, providing the exact byte interval ([src/client/nclient.c:1870](../../src/client/nclient.c#L1870), [src/common/sockbuf.c:901](../../src/common/sockbuf.c#L901)).

## State authority and ownership

| Class | Authoritative payload | Derived presentation (never the source of truth) | Clear/update rule |
|---|---|---|---|
| Snapshot | vitals, stats, identity, world position, conditions, currency, flags, audio selections | labels, bars, colours, warning animations/sounds | replace atomically per packet; clear on session teardown |
| Keyed collection | inventory/equipment/store/subinventory slots, skills, party rows, map cells, palette entries, uniques | sorted rows, slot letters, glyph quads, bonus tables | replace addressed key; protocol empty/end marker performs deletion/batch commit |
| Modal request | item/spell/direction/amount/number/string/confirmation prompts | dialog layout, focus ring, key hint | one active request identity; response or `PKT_REQUEST_ABORT` clears |

### Definitive directionality of packet names without a client play binding

This is the exhaustive complement of the 117 named client `Receive_init` keys against top-level numeric definitions from `PKT_UNDEFINED` onward. Direction is established from the server's connection-state receive tables, concrete server senders, direct client handshake consumers, and dead-code searches—not inferred from packet number. The server initializes every absent receive entry to `Receive_undefined`, which reports and discards the unknown command ([src/server/nserver.c:302](../../src/server/nserver.c#L302), [src/server/nserver.c:6411](../../src/server/nserver.c#L6411)). The only server→client serializer outside the atomic/pre-play ledgers is dormant `PKT_LEAVE`: a source-wide symbol audit finds only its declaration and definition. If reactivated, its `%c%hd` (`packet,id`) frame would make the client send `PKT_UNKNOWNPACKET`, request redraw, and discard the entire receive buffer; it therefore remains an explicit compatibility gap rather than semantic presentation state ([src/server/netserver.h:199](../../src/server/netserver.h#L199), [src/server/nserver.c:4796](../../src/server/nserver.c#L4796), [src/client/nclient.c:1861](../../src/client/nclient.c#L1861), [src/client/nclient.c:1867](../../src/client/nclient.c#L1867)). `PKT_PRAY` is the inverse stale path: the client serializer exists, but the server has no binding and invokes `Receive_undefined` ([src/client/nclient.c:7872](../../src/client/nclient.c#L7872), [src/server/nserver.c:302](../../src/server/nserver.c#L302), [src/server/nserver.c:6411](../../src/server/nserver.c#L6411)).

## Newly surfaced specification gaps

1. Decide whether to delete dormant `PKT_LEAVE`/stale `PKT_PRAY` or implement both endpoints; reactivating either today triggers an unknown-packet discard on the opposite side.
2. Define a framed raw-payload envelope before replacing `Packet_scanf`; current bounded strings silently truncate, so byte-for-byte fallback cannot be retrofitted after decoding.
3. Specify batch delimiters and deletion markers explicitly for map rows, player lists, guild adders, skills, store and inventory collections; the receiver currently encodes them through sentinel values/control flow.
4. Separate privileged control events (portal credentials, server-injected keys, file writes/reloads) from ordinary presentation state and require allow-list/security tests.
5. Reconcile the unconditional `PKT_SANITY` registration with the `SHOW_SANITY`-conditional implementation for every target build.
6. Give ordered transient events sequence numbers; snapshots may coalesce, but sound, flash, weather, message, confirmation and macro-failure events may not.
7. Treat packet-version predicates as decoder schema selection, not renderer branches; acceptance must replay at least one fixture per row in the variant ledger.
