# SV file ownership: factual draft

> Review precedence, 2026-09-20: this source-audit draft retains historical proposals. The current consolidated contract is [persistence contract](../persistence-contract.md), based on ticket answers through Q40. In particular, display options DO affect SV, fonts import into BOTH roles, startup is fullscreen, Lanczos maps to Linear, own CFG/OPT conversion is Save-only, and server file transfer retains original behavior WITHOUT the proposed new allow-list. Do not implement superseded proposals below.

Status: bounded planning draft for [Specify persistence ownership and UI configuration schema](../issues/25-specify-persistence-ownership-and-ui-configuration-schema.md#comments), checked against source on 2026-09-20. Latest ticket Comments override its older Question. This is a file/operation inventory, not production changes or a claim of runtime compatibility. No real profile, secrets or personal history was read.

## Approved boundary and concrete path proposal

- U = existing SDL3 user root: TOMENET_SDL3_USER_PATH, otherwise SDL_GetPrefPath. G = executable installation root; B = selected game library, normally adjacent G/lib. These roots remain shared according to the established packaging rules; independent installations need not share B.
- S = U/sv. Approved main configuration: S/tomenet.cfg, SDL3 CFG syntax. Independent OPT, chat-input history and guide bookmarks also belong under S.
- Technical layout proposal: place OPT/history/bookmarks directly in S, keeping their prior basenames: S/global.opt, S/global-sv.opt, S/<character>.opt, S/<class>.opt, S/chathist-<account>.tmp, S/bookmarks.tmp. These exact names are a reviewable implementation proposal; no separate product approval is needed merely to choose nesting.
- Main CFG and OPT save only through explicit settings Save. Preview applies immediately; Cancel restores entry state; normal exit neither saves those settings nor adds a prompt. The approved credential and baseline personal-file write lifecycles are separate.
- Macros, INS, DNA, resources, pack event configs and per-event audio overrides remain shared. Normal preference loading keeps permitted load-time effects. Legacy Term-window directives do not create SV windows. Explicit external migration is data-only and leaves its source unchanged.
- Private notes and exports remain in the common user directory. Notes retain automatic append. New exports must not silently overwrite existing files.
- Latest defaults: fullscreen with a window/fullscreen choice, all unspecified defaults inherited from SDL3; imported main Term font maps to both font roles. UI dimensions follow HTML. Legacy Lanczos imports as Linear. Discovery covers known SDL3/X11 settings locations; it is not an installation-wide resource search.

Root evidence: [client.c](../../../src/client/client.c#L1325), [SDL3 user directories](../../../src/client/c-files.c#L905). The ticket Comments remain the authority for approvals; proposals here fill technical detail without reopening approved choices.

## Resolve ownership before every filesystem operation

my_fopen only redirects a path prefixed by B. It derives the matching U path, opens an existing user override, falls back to B for read-only access, and creates/copies into U for writes. Other paths open directly. It does not redirect raw fopen, stat/existence checks, rename, remove, helpers or directory scans. [c-files.c](../../../src/client/c-files.c#L424)

1. Do not globally rebind ANGBAND_DIR_USER to S: that would also relocate shared macros, INS, DNA, notes, exports and resources.
2. options_dump checks existence through redirected my_fopen, then calls raw rename on the original logical B path. Its backup can target a different location from its actual write. Resolve the concrete owned destination once, then use it for every read/stat/backup/create/replace/delete.
3. Macro dump already explicitly uses ANGBAND_USER_DIR_USER in SDL3, whereas macro metadata readers and stage operations have additional raw paths. Correct all routes as an ownership operation, not a generic fopen substitution.
4. Audit old CFG call sites: [startup minimal write](../../../src/client/c-init.c#L3677), [quit write](../../../src/client/c-init.c#L3485), [SDL shutdown](../../../src/client/main-sdl3.c#L5058), [pack selection](../../../src/client/c-util.c#L19804), [manual save](../../../src/client/c-util.c#L17115). They must respect explicit Save for SV settings; credentials use vault writes instead. This does not disable independently approved resource/history/bookmark/notes/DNA writes.
5. Preserve unknown compatible CFG fields, and do not overwrite incompatible-format source. Never copy legacy passwords into S CFG or temporary/backup snapshots. First-run default creation, conversion and shutdown are part of the same exclusion.
6. Move raw history/bookmark readers together with their writers. Existing SDL3 temp-reader/user-writer asymmetry is a source defect, not the intended SV contract.

Atomic publication, unique temporary names and safe path escaping are implementation choices. Real product consequences still needing clear wording are same-setting concurrent conflicts and whether a multi-file import is all-or-nothing or reports independent group success. These should not be conflated with asking permission for routine file naming.

## Preference loading and conversion

Current order: defaults → pref.prf/includes → global.opt → pref-<sys>.prf → font/graphics PRFs → global-<sys>.opt. Character OPT loads before early Send_options, loads again when character information arrives, then global/race/trait/class and character PRFs follow. Form PRFs may load later. [main order](../../../src/client/c-init.c#L212), [early character load](../../../src/client/c-init.c#L4407), [player order](../../../src/client/c-init.c#L308), [form loader](../../../src/client/c-files.c#L1855)

Independent OPT replaces owned option sources and destinations in that lifecycle; it does not turn ordinary shared preference loading into migration. Shared macros keep their approved session effects and load order. Merely adding global-sv.opt at the old system hook cannot guarantee final precedence, because character and PRF inputs follow it. SV layout remains authoritative for actual geometry.

The common parser accepts includes, options, mappings, macro data and load-time actions regardless of extension. Includes recurse before the macro-exclusive filter; X/Y apply runtime values immediately. Deprecated names can cause options_dump on any OPT or options.prf, regenerating the merged snapshot and losing unknown records/includes/mixed data. [parser](../../../src/client/c-files.c#L1049), [conversion](../../../src/client/c-files.c#L1793)

Technical contract to carry into implementation: each normal load has source ownership and a conversion destination. SV OPT conversion stays in S; shared permitted PRF effects remain; old options.prf reached through a default include cannot receive an SV snapshot. Shipped defaults and legacy user options overrides must be distinguishable. Explicit external migration never invokes a side-effecting loader against its source. Normal shared INS/DNA auto-conversion remains as approved. No blanket suppression of shared macro actions is introduced here.

## Server file transfer destinations

Receive_file accepts INIT/DATA/END/CHECK/SUM, uses existing acknowledgements and honors no_lua_updates for INIT. END reopens Lua after transfers finish and keeps audio/guide refresh behavior. [nclient.c](../../../src/client/nclient.c#L477)

local_file_init rejects leading slash and any '..', creates tomexfer.XXXXXX in CWD, and stores the received path. Final close maps legacy Windows user/scpt paths or B+filename, then my_fopen writes the destination. Checksum requests use the same mapping but do not pass through INIT validation. This is not an owner allow-list or atomic destination replacement. [mapping](../../../src/common/files.c#L128), [INIT](../../../src/common/files.c#L415), [publication](../../../src/common/files.c#L476), [checksums](../../../src/common/files.c#L545)

The checked-in server update list consists of explicit scpt/*.lua paths in [update.lua](../../../lib/scpt/update.lua#L1). Generic transfer capability is wider than that list.

Proposed client-side boundary: one canonical resource resolver/allow-list for both CHECK and INIT, permitting the current script updates and any additional evidenced baseline resource destinations; forbid S, credentials and personal files. Validate both platform path syntaxes and containment before access, and publish through a temporary beside the actual shared destination. This changes client validation/routing only: zero server changes, no packet changes. Do not claim an exact-list restriction covers every deployed server without evidence; accepting the approved script subtree is an alternative compatibility scope.

## Audio, caches and guide

Pack configs/event-volume overrides are shared by approved Q32. Existing writer uses fixed os_temp_path/sound.cfg or music.cfg, copies to user pack config with .bak, then separately truncates/writes the volume file. These temporary names can collide across clients; the pair is not one transaction. Preserve shared content semantics while using resolved owners, unique intermediates and explicit failures. Pack selection itself remains independent main CFG and Save-only. [audio writer](../../../src/client/snd-sdl3.c#L4109), [pack installation](../../../src/client/c-util.c#L16485)

Graphics cache already has unique sibling temporary publication and version/source/context identity; that is evidence for current cache compatibility only, not proof a new renderer can reuse the same key. [key/load](../../../src/client/main-sdl3.c#L2666), [publish](../../../src/client/main-sdl3.c#L2706)

Guide mismatch: init_guide reads CWD TomeNET-Guide.txt; normal SDL3 CWD is G. The SDL3 updater writes G/TomeNET-Guide.txt, outside B-prefix redirection. Checksum tries U/TomeNET-Guide.txt, then B, then G. Thus a user override may be checksummed while a different guide is displayed/updated. [viewer](../../../src/client/c-init.c#L2985), [updater](../../../src/client/c-util.c#L17193), [checksum](../../../src/client/c-files.c#L3726)

Technical proposal: use U/TomeNET-Guide.txt as writable shared override, falling back to the selected bundled B/G guide, with one resolver for viewer/check/update/backup/rollback. Publish download only after validation, leaving the effective previous file intact on failure. This is a proposed correction, not current source behavior. A legacy reader still opening only G will not see the U override; if cross-client visibility of guide updates is required, that is a genuine compatibility decision rather than a filename detail.

## Credentials and excluded outputs

Account secrets belong only to Linux Secret Service / Windows generic Credential Manager according to [Define credential storage policy](../issues/24-define-credential-storage-policy.md#answer). Normal startup never reads a legacy password into login state. Explicit password import is a distinct protected-store group, with a nonsecret preview and unchanged source. Failure uses session-only input, never open-file fallback.

Exclude secrets and reversible representations from CFG/OPT creation/conversion, .bak/.$$$ drafts, import reports, presentation events, diagnostics and auth-payload logging. Nonsecret account/server metadata does not authorize a secret file. Identity serialization must preserve distinct baseline accounts and server/port identities, including Windows case-insensitive vault target matching; this is a technical schema requirement, not a reason to ask the user to choose an encoding.

Archive/audio-pack passwords remain temporary private input, never common history. No new exporter, recorder, credential-delete UI or secret-transfer file is added. Ordinary gameplay exports remain available; the exclusion concerns actual credential fields.

## Remaining decision versus implementation detail

- Technical choices that can be specified directly: exact S subpaths, owner-resolver interface, reserved default include routing, identity serialization, unique temporary naming, atomic replacement where supported, compatible cache versioning and source-reference layout.
- Decisions with observable product consequences still need alignment with the main ticket: import preview/group failure and reimport conflicts; concurrent shared-file/same-SV-setting conflicts; guide update visibility across legacy/SV; permitted non-script server-file destinations if baseline needs them.
- Already approved and not reopened: independent CFG/OPT, same syntax, explicit Save, shared macro effects, shared INS/DNA/audio-resource preferences, private input history/bookmarks, shared notes/exports, fullscreen choice and defaults from SDL3.
