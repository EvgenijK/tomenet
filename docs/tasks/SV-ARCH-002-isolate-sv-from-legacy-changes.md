# SV-ARCH-002 — Убрать изменения legacy и common, внесённые ради SV

**Статус:** implemented; Linux acceptance passed, Windows verification blocked by dependencies.
**Дата:** 2026-09-22.
**Тип:** корректировка реализации Stage A, тикеты 02–04.
**Зависимости:** тикеты 02–04 реализованы; незавершённых блокеров нет.
**Основание:** [правило изоляции SV](../../AGENTS.md),
[SV-IMP-001](../sv-improvements.md#sv-imp-001--локализовать-существующие-sv-зависимости-от-вынесенных-helpers).

## Проблема и результат

Ради общего production-кода SV и legacy были изменены `src/client/nclient.c`
и `src/common/common.c`. Декодирование HP, сообщений, key request и сериализация
ответа вынесены в общие helpers; сравнение версий подключается через `.inc`.
Проверки границ строковых полей при этом изменили поведение legacy-клиента.

Нужно локализовать эти реализации внутри SV и убрать обусловленные ими изменения
существующего клиента и common. SV сохраняет текущие возможности и безопасную
обработку пакетов. Локальное дублирование baseline-кода допустимо ради изоляции;
сокращение числа копий не является целью этой задачи.

## Исходное состояние

На момент постановки HEAD — `e12f232f7`, включающий merge upstream
`59473651d`. Изменения появились в `15c6730f1`, `d7b2b9c50`, `5c4b069ac`.
Перед работой зафиксировать актуальные ревизии и проверить рабочее дерево.
Восстанавливать конкретные участки, сохраняя последующие upstream-изменения
и постороннюю работу; не заменять целые файлы версиями из старого коммита.

| `src/common/common.c` | Вернуть определение `is_newer_than()` вместо включения `version-newer.inc`, сохранив алгоритм |

| SV protocol/model, build и tests | Обновить зависимости и вызовы; сохранить production-путь, проверяемый существующими сценариями |

## Обязательное поведение

- Сохранить оба HP wire layouts, значения/маркеры, порядок применения и alerts.
- Сохранить исходные message bytes, отдельные повторные occurrences,
  ограниченную обязательную доставку и независимость redraw от consumption.
- Сохранить request identity/prompt, точные reply bytes, Escape и owner-specific
  server abort, parent context и обновление HP во время ожидания.
- В SV сохранить проверки NUL в допустимом slot для message и key request:
  incomplete ждёт без частичного apply, malformed вызывает явную ошибку.
- В SV сохранить семантику `is_newer_than`, включая `major == 0` и пороги версий.
- Сохранить разделение Protocol, Session, input router, Application и UI,
  изолированные build outputs и отсутствие terminal fallback.

При восстановлении legacy-вызовов новые проверки строковых границ перестанут
применяться к этим legacy-путям. Явно отразить это в SV-IMP-002 списка улучшений:
защита остаётся в SV, исправление legacy scanner/handlers остаётся отдельной
задачей. Не обозначать этот пункт как исправленный для legacy.

## Проверки и границы тестирования

Использовать уже согласованные seams: production SvApp/Session/input router,
native scenario и существующий legacy regression harness. Тесты вызывают
реальную локальную SV-реализацию; отдельного тестового декодера не создавать.
Существующие assertions не ослаблять ради переноса файлов. Добавлять проверки
при обнаружении непокрытого риска поведения, а не для фиксации структуры кода.

- Собрать Linux SV и legacy SDL3. Проверить MinGW при наличии зависимостей;
  отсутствие зависимостей записать как ограничение, не как успешную проверку.
- Запустить headless architecture/message/request checks с санитайзерами
  и legacy HP regression.
- Запустить native HP/message/request/architecture и shell/resource checks
  на software и OpenGL. В конце выполнить весь доступный SV regression suite.
- Проверить diff относительно выбранного baseline: в `nclient.c` и `common.c`
  не остаётся перечисленных SV-вставок, посторонние изменения сохранены.
- Проверить ссылки/include/build dependencies после перемещения и удаления
  helpers. Обычное использование неизменённых common-модулей разрешено;
  полное отделение SV от всех общих исходников не требуется.

## Результат — 2026-09-22

Исходная ревизия `e12f232f747d93c92b4a9f1695ebe3b42261a810`, ветка
`modern_interface`. Восстановлены только целевые участки. Проверка
`git diff 59473651d -- src/client/nclient.c src/common/common.c` пуста:
оба файла совпадают с актуальным upstream, включая независимые изменения.
Helpers перенесены в `src/client/sv`, переименованы в `sv_*`; алгоритмы
и строгие проверки полей сохранены. Сравнение версий скопировано без изменения
в SV `version.c`, общий `.inc` удалён. Legacy HP harness линкует `common.c`.
Makefile использует compiler-generated dependencies (`-MMD -MP`), поэтому
дополнительных build rules для локальных headers не требуется.

Linux SV и полный legacy SDL3 build прошли. Все 14 доступных regression runners
прошли: architecture/message/request ASan+UBSan+LeakSanitizer, legacy HP,
нативные HP/message/request/architecture и shell/resource на software и OpenGL.
На каждом backend: HP 78 случаев / 156 кадров, message 18 / 54, request 40 / 120.
Request sanitizer: 372 fragmentation cases. LeakSanitizer запускался вне
ptrace-песочницы через штатную escalation; первоначальный sandbox-запуск
не дал evidence из-за ограничения LSan. Существующие assertions не ослаблены.

MinGW build предпринят: отсутствуют cross SDL3/SDL3_ttf/FreeType development
dependencies. Новых Windows/Wine результатов нет. Исторические проверки
в документах сохранены отдельно. Логи текущего прогона:
`/tmp/sv-arch002-check-01.log` … `/tmp/sv-arch002-check-14.log`,
`/tmp/sv-arch002-build.log`, `/tmp/sv-arch002-build-legacy.log`,
`/tmp/sv-arch002-mingw.log` (временные локальные артефакты).
