# Domain docs

This is a single-context repo: the glossary is `CONTEXT.md` at the root and architecture decisions are in `docs/adr/`. No `CONTEXT-MAP.md` is needed.

Before exploring or changing a domain concept, read `CONTEXT.md` and ADRs relevant to the work. Use the glossary's terms in tickets, tests and proposals. Surface a conflict with an ADR explicitly.

Wayfinder's resolved decision tickets in `.scratch/<effort>/issues/` hold planning answers; their map is an index. SV implementation requirements and evidence live with their tickets in `docs/tasks/`. Follow the priority rule in `AGENTS.md` when an older planning decision conflicts with it.
