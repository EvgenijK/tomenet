# Диагностическая обвязка SV

Здесь находятся проверочные инструменты, вынесенные из `src/client/sv` и
`src/temporary/sv`:

- `launcher.[ch]` — существующий CLI с синтетическими сценариями и review-режимом;
- `runtime.[ch]` — сбор результатов сценариев и JSONL-отчёт;
- `timing.[ch]` — измерение времени от production-события до отправки кадра;
- `ui.[ch]` — синтетическая оболочка Stage A и виртуальный DPI;
- `capture.[ch]` — настройка и сохранение диагностических кадров;
- `synthetic.[ch]`, `peer.c` — изолированный bootstrap и подготовленные wire bytes.

Сценарии остаются в `tests/sv/scenarios/`. Обвязка вызывает production-пути
приложения, протокола, ввода и отрисовки; отдельной реализации игрового поведения
здесь нет. Типы сценариев, формат отчёта, переменные захвата и readback не входят
в production API. Там остаются общие точки наблюдения и защита lifetime.

Текущая сборка `makefile.sv` явно перечисляет диагностические objects отдельно
от `SV_CLIENT_OBJECTS`. Для сохранения CLI короткая точка входа `src/client/sv/main.c`
пока вызывает этот launcher, включая запуск `--endpoint`.
Перенос исходников не означает исключения обвязки из текущего executable.

Доступ к кадру разрешён только при замаскированных приватных полях. Любая ошибка
захвата сохраняет прежнее поведение: кадр не отправляется renderer'у.
