# Font, map glyph and tiles contracts in the existing backends

This is a factual audit of current SDL3 and applicable X11 code, not a decision about the new single-window configuration. Existing independence is **per logical Term**, whose SDL3 implementation currently owns a system window. The main Term includes map cells and text outside the map; there is no separate main-Term text-font versus map-font field evidenced here. A single system window does not inherently require merging these rendering roles or their font resources.

## Current controls and scopes

| Area | Evidence and current behavior |
|---|---|
| Font selection | [SDL3 per-Term font environment variables](../../../src/client/main-sdl3.c#L1014), [startup precedence](../../../src/client/main-sdl3.c#L4059): specific Term environment, common `TOMENET_SDL3_FONT`, saved Term preference, default. Each `term_data` loads its own font at [initialization](../../../src/client/main-sdl3.c#L3726). [X11](../../../src/client/main-x11.c#L1302) also has per-Term names and defaults. |
| User font menu | [Menu](../../../src/client/c-util.c#L13712) selects a window/Term with up/down, changes font with smaller/bigger keys, or accepts a specific name with Enter. It displays each Term's current font. This provides independent auxiliary-Term versus main-Term font choice, not independently configurable regions within the main Term. |
| TTF/PCF | [TTF loading](../../../src/client/main-sdl3.c#L505) parses filename and point size, looks in user directory before bundled directory, scales by display content scale, and derives cell metrics. [PCF loading](../../../src/client/main-sdl3.c#L627) adds `.pcf` if needed, uses the same directory precedence, and derives width/height from bitmap glyph metrics. [Dispatch](../../../src/client/main-sdl3.c#L804) distinguishes formats. |
| Live font change | [SDL3 `term_force_font`](../../../src/client/main-sdl3.c#L4701) loads the new resource before replacing the old one; failure retains the old font. Metric changes resize the Term window at its existing logical cell counts and rebuild graphics. Main font change additionally reloads visual preferences. [`set_font_name`](../../../src/client/main-sdl3.c#L4946) saves preferences for hidden Terms, applies visible changes, and redraws the affected Term. [X11 selection](../../../src/client/main-x11.c#L5264) similarly targets the selected Term. |
| Saved preferences | [SDL3 save](../../../src/client/main-sdl3.c#L1574) records Term dimensions, position and font name. Defaults are [per Term](../../../src/config.h#L870). |
| Graphics mode | [SDL3 mode switch](../../../src/client/main-sdl3.c#L4393) changes the global graphics mode and rebuilds assets. [Graphics menu](../../../src/client/c-util.c#L15124) stages mode changes and applies with `p`; `f` opens the font menu for zooming. The non-SDL3 branch explicitly requires restart rather than unsafe live changes. This is distinct from selecting a font. |

## Mixed map glyphs and tiles

Graphics mode installs `higher_pict=true`, plus picture and raw-picture hooks; it does not replace the text hook with a tiles-only renderer ([SDL3 hooks](../../../src/client/main-sdl3.c#L3662), [X11 flag](../../../src/client/main-x11.c#L3784)). The shared renderer dispatches foreground IDs above `MAX_FONT_CHAR=255` to picture hooks; IDs at or below that threshold remain byte text ([shared dispatch](../../../src/client/z-term.c#L2177)). Pending byte text runs are flushed before drawing a tile. Thus tiles may coexist with text in the same Term, including map glyphs that retain font IDs, text outside the map, and ASCII weather. Which particular monsters, items or terrain use tiles depends on loaded visual definitions, not simply on their semantic object class.

The ordinary font renderer does not know whether a byte stands for an actor, item, terrain or message character. That distinction comes from the producer/visual mappings and surface context. Consequently independent semantic text-font and map-font settings in one composed window would need explicit role selection; the present implementation's per-Term font is not evidence of such an intra-Term setting already existing.

## Visual definitions legitimately change on main-font switches

[`handle_process_font_file`](../../../src/client/c-util.c#L20207) clears existing terrain, monster, item and unknown-item mappings, reverse-map dictionaries and subtileset assignments. With `char_map_offset=0`, it derives `font-custom-<main-font-name>.prf`, loading that file if present or falling back to `font-<backend>.prf` ([lookup](../../../src/client/c-util.c#L20245)). If graphics are enabled, graphics preferences load **after** the font preferences ([ordering](../../../src/client/c-util.c#L20280)). In-game it sends `Send_client_setup`, and at function end it sends `Send_font` ([notifications](../../../src/client/c-util.c#L20286)). SDL3 calls this after a successful main-font replacement even when metrics remain unchanged ([switch hook](../../../src/client/main-sdl3.c#L4757)); `set_font_name` then redraws.

[Graphics preference loading](../../../src/client/c-util.c#L20120) clears old raw-picture definitions and SDL3 mask preferences, loads `graphics-<tileset>.prf` and enabled subset preference files with `char_map_offset=MAX_FONT_CHAR+1`, finalizes SDL3 graphics resources, resets the offset, and caches weather pseudo-object glyph definitions. This preserves a font-based mapping layer followed by graphics overrides; it does not mean every glyph has a tile override.

Therefore a configured main/map font change can intentionally change gameplay visual definitions sent to the server. That is separate from Unicode decoding: converting a received legacy byte for display does not itself authorize remapping its game identity. Auxiliary-Term font selection does not trigger this main-font visual-pref reload in `term_force_font`.

## Cell metrics, composition and effects

| Operation | Current invariant and source |
|---|---|
| Text cells | [SDL3 placement](../../../src/client/main-sdl3.c#L828) uses active font width/height plus border offsets and clips runs to the requested cell rectangle. [X11](../../../src/client/main-x11.c#L1064) draws bytes with explicit length, using individual cell placement when emulating monospace. |
| Tile size/zoom | [SDL3 tileset preparation](../../../src/client/main-sdl3.c#L3513) scales source tile dimensions to the selected Term font's width/height. Layers, preparation surfaces and caches are sized accordingly ([allocation](../../../src/client/main-sdl3.c#L3638)). Tile draw coordinates likewise use font metrics ([draw](../../../src/client/main-sdl3.c#L2137)). Current font zoom therefore also changes tile geometry in that Term; no separate tile-zoom control is established by these paths. X11 similarly computes resized image dimensions from font dimensions ([scaling](../../../src/client/main-x11.c#L3380)). |
| Single layer | [SDL3](../../../src/client/main-sdl3.c#L2095) translates glyph ID to tile index by subtracting 256, resolves attr colors and subset selection, and composes the tile in one cell. |
| Two layers | [SDL3](../../../src/client/main-sdl3.c#L2147) retains separate foreground/background IDs and attrs, draws terrain before foreground, uses only the bottom layer's background fill, and makes the foreground background transparent. `c_back=32` or `0` skips the background tile locally; packet-level zero semantics must be handled before rendering. Foreground and background can independently select subtilesets. [Layer drawing](../../../src/client/main-sdl3.c#L2044) uses a subset's own sheet/tiles-per-row with fallback to base assets when unavailable. X11 has an actual two-mask compositor, not merely a fallback stub ([implementation](../../../src/client/main-x11.c#L2516)). |
| Solid glyph | [SDL3 text hook](../../../src/client/main-sdl3.c#L1826) treats `FONT_MAP_SOLID_X11` as a filled cell block, splitting mixed runs around that byte. This appearance is independent of the font bitmap or a proposed Unicode replacement. |
| Cursor | [SDL3 cursor](../../../src/client/main-sdl3.c#L1745) draws a translucent rectangle of active font cell size; duplicate placement is suppressed. Text drawing updates cursor tracking ([text lifecycle](../../../src/client/main-sdl3.c#L1846)). |
| Raw pictures | [SDL3 raw-picture hook](../../../src/client/main-sdl3.c#L2249) anchors at cell coordinates using active font metrics but draws a separate picture rectangle that may exceed a single cell. Picture scale/metadata are prepared with the selected Term's tileset geometry. These are not font glyphs. |
| Weather | [Weather drawing](../../../src/client/c-xtra1.c#L5543) can choose two-mask tiles, single tiles or byte glyphs according to graphics mode, available pseudo-object definitions, `ascii_weather` and `no2mask_weather`. It restores underlying map cells when moving/removing particles. Thus ASCII weather can use the font while the map uses tiles; a tile-enabled map does not eliminate its font dependency. |
| Animated attrs/palette | Original attrs remain distinct from their frame-resolved colors; effects and palette updates can change appearance without new glyph identities. Detailed evidence is in [renderer parity](renderer-parity.md). Font choice alone cannot substitute for the complete composition context. |

## Text representation boundary and evidence limits

Legacy `Term_addstr` copies unsigned bytes into one logical cell each ([implementation](../../../src/client/z-term.c#L3256)); `Term_putstr` interprets supported inline color markers ([parser](../../../src/client/z-term.c#L3296)). Server documents, chat and other existing formatted surfaces using this pipeline are byte-oriented surfaces even when they are semantically text. Their font/encoding contract is distinct from game glyph identity, but they are not already general Unicode-layout surfaces.

Own Unicode UI labels are a proposed new UI role; the existing SDL3 Term text path does not establish that role. Its TTF branch passes raw bytes to a UTF-8 API, while PCF indexes byte glyphs ([existing discrepancy](../../../src/client/main-sdl3.c#L854)). Preserving the appearance of configured byte fonts cannot be demonstrated by blindly converting all bytes to the same Unicode codepoints. [Complete asset metadata audit](encoding-font-assets.md) documents the font diversity without claiming bitmap equivalence.

This audit did not run visual acceptance, change configuration, choose a new interface, or claim pixel equality across X11/SDL3 rasterizers. Single-window role boundaries, independent role settings and any separate map/tile zoom remain product decisions. Their assessment must account for the current mixed font/tile path, main-font-specific visual mappings and cell-sized effects described above.
