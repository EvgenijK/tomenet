# Атомарная renderer parity для single-window SDL3

## Результат и границы доказательств

Renderer parity — это сохранение наблюдаемой информации и поведения каждой операции рисования при её применимых compile-time, server-version и пользовательских gates. Единый эталон «все пиксели X11 = все пиксели SDL3» отсутствует: X11 и SDL3 уже различаются растеризацией шрифтов, курсором и композицией outline. Для нового SDL3 renderer нужны точные проверки модели/порядка операций и отдельные raster fixtures при фиксированных шрифте, palette, масштабе и backend. Это вывод из перечисленных ниже реализаций, а не уже принятое продуктом решение о допустимых отклонениях.

Исследованы актуальные локальные `main-x11.c`, `main-sdl3.c`, `z-term.c`, `nclient.c`, `c-files.c`, `c-cmd.c`, `c-xtra1.c`, `config.h`, common defines и server cave. Реализация в этом checkout — первичный источник; номера строк привязаны к нему. Runtime acceptance не выполнялась, неизвестные font/backend combinations не объявляются работающими. Производительность и численные допуски не выводятся из чтения кода. Единственный внешний факт проверен по официальной документации SDL_ttf: контракт UTF-8.

## 1. Представление и операции, которые нельзя свернуть в «цветной текст»

Общий terminal хранит отдельные requested/old/saved массивы атрибутов и `char32_t` символов; при `GRAPHICS_BG_MASK` имеются соответствующие background массивы. Они участвуют в сравнении, repaint и screen save/restore [src/client/z-term.c:318](../../../src/client/z-term.c#L318), [src/client/z-term.c:433](../../../src/client/z-term.c#L433), [src/client/z-term.c:477](../../../src/client/z-term.c#L477), [src/client/z-term.c:4680](../../../src/client/z-term.c#L4680). Сохранить только RGB и строку недостаточно: теряются исходный animated attr, glyph/tile identity, background и возможность заново вычислить кадр.

## 2. Encoding и control codes

`Term_addch` преобразует unsigned byte в `char32_t`; `Term_addstr` копирует каждый unsigned byte отдельно [z-term.c:3203](../../../src/client/z-term.c#L3203), [z-term.c:3256](../../../src/client/z-term.c#L3256). `MAX_FONT_CHAR=255`; значения выше порога используются как graphical tile ids, а не автоматически Unicode [src/common/defines.h:8661](../../../src/common/defines.h#L8661), [z-term.c:1719](../../../src/client/z-term.c#L1719).

`Term_putstr` разбирает inline marker `0xff`: обычный color char меняет attr, `0xff 0xff` печатает `{`, `-` возвращает first visible color, `.` меняет местами current/previous, `%` нейтрален. Unknown color не проходит ветку успешного `color_char_to_attr` и остаётся в последующем тексте; нельзя молча удалять все неизвестные пары. Лимит `n` и положение курсора обрабатываются отдельно от marker bytes [z-term.c:3296](../../../src/client/z-term.c#L3296), [z-term.c:3336](../../../src/client/z-term.c#L3336), [z-term.c:3353](../../../src/client/z-term.c#L3353), [z-term.c:3379](../../../src/client/z-term.c#L3379). Частично icky screen также дублирует допустимые записи в underlying screen через `Term_switch`; это presentation lifecycle, а не характеристика glyph raster [z-term.c:3313](../../../src/client/z-term.c#L3313).

X11 использует byte-oriented `XDrawImageString` с явным `len`; PCF SDL3 индексирует `glyphIndexes[(uint8_t)str[i]]`. SDL3 TTF передаёт исходный `str` в `TTF_RenderText_LCD(...,0,...)`, где `0` означает NUL termination, а API принимает UTF-8 [main-x11.c:1064](../../../src/client/main-x11.c#L1064), [main-sdl3.c:854](../../../src/client/main-sdl3.c#L854), [main-sdl3.c:5905](../../../src/client/main-sdl3.c#L5905), [официальный контракт TTF_RenderText_LCD](https://wiki.libsdl.org/SDL3_ttf/TTF_RenderText_LCD). Следовательно high-byte glyph strings могут иметь различное значение в PCF/X11 и TTF. Одно название `char32_t` не доказывает Unicode поддержку. Нужен самостоятельный encoding decision: как сохранять legacy glyph id и как преобразовывать его для Unicode UI. До него нельзя обещать TTF parity для всех 256 значений.

Acceptance: начальный цвет; несколько transitions; reset first/previous; repeated swap; neutral marker; literal brace; unknown code; `n` на границе transition; high bytes; NUL termination; solid-wall байт; tile id выше 255. Некорректные marker tails и ошибки подсчёта следует описать как defect fixtures и отдельно решить, сохраняется ли результат или исправляется дефект.

### Wire gates

`Receive_char` поддерживает старый byte transfer, peers ≥4.8.1 с 1/2/3/4 transfer bytes и ≥4.9.2.1 two-mask foreground/background в `UG_2MASK` при `GRAPHICS_BG_MASK` [nclient.c:3162](../../../src/client/nclient.c#L3162). `TERM_HILITE_PLAYER` для peers ≥4.7.3 снимается с attr и становится отдельным highlight signal. `TEST_CLIENT` содержит cross-platform solid/vein remapping [nclient.c:3233](../../../src/client/nclient.c#L3233). `PKT_CHAR_DIRECT` не обновляет ordinary panel buffer; для обычной карты `c_back==0` означает сохранить прошлый background, а не erase [nclient.c:3277](../../../src/client/nclient.c#L3277). Это packet-level семантика, которую renderer fixtures должны получать уже правильно декодированной.

## 4. Palettes, animations и lighting

`term2attr` переводит TERM semantic attr в palette index: base direct, palette-animated clones в 16..31 при `EXTENDED_COLOURS_PALANIM`, experimental background colors при `EXTENDED_BG_COLOURS`, animated values через `flick_colour` [z-term.c:289](../../../src/client/z-term.c#L289). Поэтому хранить resolved index/RGB вместо original attr нельзя. В SDL3 text/tile hooks применяют masks 0x0f/0x1f/0x3f в соответствующих комбинациях defines [main-sdl3.c:1806](../../../src/client/main-sdl3.c#L1806), [main-sdl3.c:2180](../../../src/client/main-sdl3.c#L2180). Base palette равна 16; дублирование и experimental ranges условны, не единая всегда доступная таблица [common/defines.h:8479](../../../src/common/defines.h#L8479).

Palette update меняет `color_table[c][1..3]` и drawable colors. `127/128` — refresh markers, не обычные entries; main repaint включает UI для full palette flash/lightning и выбирает repaint/redraw по `gfx_palanim_repaint`, `gfx_hack_repaint`, login hack. Visibility и minimized sentinel могут подавить refresh [main-sdl3.c:5170](../../../src/client/main-sdl3.c#L5170). `refresh_palette` дополнительно redraw всех visible terms [main-sdl3.c:5269](../../../src/client/main-sdl3.c#L5269). X11 имеет аналогичный palette hook и собственную tile invalidation [main-x11.c:5469](../../../src/client/main-x11.c#L5469), [main-x11.c:2730](../../../src/client/main-x11.c#L2730).

`flick_colour` учитывает `no_flicker`, `subterm_flicker`, `misc_no_flicker` и message/chat window flags, переводя animation в static attr [z-term.c:1133](../../../src/client/z-term.c#L1133). `flicker` проходит terminals/cells, учитывает animated foreground и background, пропускает spaces ради raw casino pictures, использует pict hook для tile ids и text hook для glyphs. Lamp randomness зависит от wind; lamp fainting и ticks влияют на последующие цвета [z-term.c:1638](../../../src/client/z-term.c#L1638). Searchlight использует grid coordinates и временные counters; big-map lower half сейчас дублирует pattern [z-term.c:1009](../../../src/client/z-term.c#L1009), [z-term.c:1495](../../../src/client/z-term.c#L1495). Это подтверждённое поведение старой реализации, не обязательный дизайн нового эффекта.

Обычное floor/wall lighting частично определяется сервером и user options, затем приходит в attrs/glyphs; нельзя заменять его локально придуманным lighting только по terrain [src/server/cave.c:3152](../../../src/server/cave.c#L3152), [src/server/cave.c:3317](../../../src/server/cave.c#L3317), [src/server/cave.c:3724](../../../src/server/cave.c#L3724), [c-tables.c:213](../../../src/client/c-tables.c#L213). Lightning — отдельная временная palette animation с backup/restore, защитой от overlapping strikes и reset while icky; gates `disable_lightning`, `palette_animation` [c-xtra1.c:5346](../../../src/client/c-xtra1.c#L5346), [c-xtra1.c:5376](../../../src/client/c-xtra1.c#L5376). Trigger связывается с thunder packet/sound [nclient.c:5584](../../../src/client/nclient.c#L5584).

Acceptance: original attr неизменен при frame step; same cell/no packet изменяет видимый кадр; nonanimated cells stable; animation options и subwindow policy; independent animated terrain; palette burst с marker; day/night transition; full UI flash; overlapping lightning/reset при modal screen; lamp wind и fainting. Determinism требует записать logical time, RNG либо resolved animation stages; сравнение случайно выбранных кадров без такого контекста не доказывает parity.

## 6. Raw pictures и два разных cache слоя

Raw picture выбирает `tiles_rawpict_subtileset[id]` и соответствующий scaled sheet/rectangle; invalid id/no sheet/no positive dimensions no-op, undefined picture рисует space; destination anchor клеточный, extent pixel rectangle [main-sdl3.c:2249](../../../src/client/main-sdl3.c#L2249). Metadata масштабируется по original/use sheet dimensions [main-sdl3.c:2430](../../../src/client/main-sdl3.c#L2430), [main-sdl3.c:3504](../../../src/client/main-sdl3.c#L3504). X11 имеет собственный rawpict hook [main-x11.c:2756](../../../src/client/main-x11.c#L2756). `flicker` специально не перерисовывает space cells, чтобы animated slot frame не уничтожил casino images [z-term.c:1680](../../../src/client/z-term.c#L1680).

SDL3 memory tile cache при `TILE_CACHE_SIZE`: per-term FIFO entries, key `(tile index, subset, all foreground/outline colors)`, bottom background исключён намеренно: cached layer прозрачен и накладывается поверх нового fill. Caller сравнивает resolved colors, поэтому palette changes дают иной key; old color entry допустим лишь если новая palette действительно совпадает [main-sdl3.c:1981](../../../src/client/main-sdl3.c#L1981), [main-sdl3.c:2009](../../../src/client/main-sdl3.c#L2009), [main-sdl3.c:2042](../../../src/client/main-sdl3.c#L2042). `disable_tile_cache` объявлен, но видимый SDL3 draw path под `#ifdef TILE_CACHE_SIZE` не проверяет этот runtime flag; нельзя заявлять acceptance «flag выключил memory cache» без дополнительной трассировки/решения [main-sdl3.c:922](../../../src/client/main-sdl3.c#L922), [main-sdl3.c:2047](../../../src/client/main-sdl3.c#L2047).

Disk tileset cache — отдельный слой scaled-sheet BMP. Filename содержит tileset/subset, destination tile dimensions, variant, SDL3 version, source hash и context hash. Load проверяет expected dimensions и конвертирует RGBA32; invalid load = recompute. `disable_tileset_caching` и zero source hash дают miss; variant distinguishing nearest, filtered rawpict, nomask; context включает rawpict bounds/id и omitted mask colors [main-sdl3.c:2629](../../../src/client/main-sdl3.c#L2629), [main-sdl3.c:2659](../../../src/client/main-sdl3.c#L2659), [main-sdl3.c:2744](../../../src/client/main-sdl3.c#L2744), [main-sdl3.c:3069](../../../src/client/main-sdl3.c#L3069). ## 10. Минимальная observable acceptance matrix

Единица fixture — операция + исходная модель + gates + expected model/visible region + frame context, а не скриншот обычной ASCII карты. Общий пакет покрытия:

1. Encoding/control corpus и direct-cell writes, high-byte fonts и tile ids.
2. Fixed PCF, fixed/proportional TTF, solid fill, cursor move/rewrite/restore; fixed DPI и monitor change.
3. Base/extended/experimental palettes, original animation attrs, refresh marker bursts, lighting options и timed flash restore.
4. Single/two-mask tiles, foreground/background independent updates, subtiles per layer, outline/filters и raw multi-cell pictures.
5. Cold/warm/invalid/disk-disabled caches, reload/font/filter/subset boundaries; memory-cache disabled scenario только после выяснения actual flag semantics.
6. Weather start/pregen/move/halt/stop, overlay restoration, modal suppression и map resize.
7. Server dimensions normal/big/unsupported gate, debounce/compositor/maximized handling, forced repaint и auxiliary refresh.
8. XHTML projection отдельно от real composed-window PNG/BMP и last screenshot lifecycle.

Для каждой строки gates обязательны: compile flags (`USE_GRAPHICS`, `GRAPHICS_BG_MASK`, `TILE_CACHE_SIZE`, `SDL3_IMAGE`, palette/extended-color flags, `TEST_CLIENT`, `ENABLE_SHIFT_SPECIALKEYS`, `GLOBAL_BIG_MAP`), runtime graphics mode, font asset/size, scale/surface dimensions, user options, server version/features/transfer width и clock/RNG. Неактивная branch маркируется not applicable; удаление branch или функции — самостоятельное scoping решение. Raster equality имеет смысл только для одного заданного backend/font/environment. Семантические cell ids, packet dimensions и lifecycle transitions можно сравнивать строго независимо от antialiasing.

## 11. Решения, которые теперь можно сформулировать точно

- **Зафиксировать encoding и glyph identity:** legacy unsigned-byte cell alphabet, UI Unicode conversion, mapping для control/high bytes, обработка invalid text и допустимые исправления PCF/TTF несогласованностей.
- **Определить raster oracle и допустимые отклонения:** какой SDL3 reference pipeline является эталоном для fonts/cursor/outline; какой уровень сравнения нужен против X11; какие старые defects сохранять или исправлять.
- **Зафиксировать DPI coordinate contract:** logical UI/window units, surface pixel units, cell/tile scaling и независимость server map viewport от композиции UI.
- **Выбрать retained render evidence для непостоянных слоёв:** raw pictures и weather/cursor overlays, original attrs, logical time/RNG, palette bursts; как replay обеспечивает достоверный final composed frame.

Это острые вопросы к последующим design/acceptance tickets, а не разрешение реализации. Resource budgets, конкретные tolerance values и новая архитектура caches остаются fog до интерфейсов/harness; исследование не назначает их произвольными числами.
